## General note: GitHub's web interface and hidden files

GitHub's web uploader (**Add file → Upload files**, or dragging files onto a repository page) silently skips every file and folder whose name begins with a dot, even when they are visible in Finder and included in the drag. No warning appears. In these templates that means `.github/workflows/hugo.yml` (without it nothing builds), `.pages.yml` (without it Pages CMS has no forms), `.gitignore`, and `.gitkeep` placeholders.

Ways to get them in:
- **Claude pushes them** from a session with the repository attached.
- **Add file → Create new file**, one at a time: type the full path as the name (e.g. `.github/workflows/hugo.yml`; each `/` makes a folder) and paste the contents. The web interface does accept dot-files this way; only the uploader drops them.
- **Use this template** (for students): copies every file, hidden ones included.
- **GitHub Desktop**: add the unzipped folder (File → Add Local Repository; Desktop offers to create a repository), commit and publish; hidden files go with it.

## A. One-time account setup

1. **Pages CMS access.** The Pages CMS GitHub App should be installed with **Only select repositories**, so each new repository must be added to its list. Forgetting this is the most common reason a repository doesn't appear in Pages CMS. To add one:
   1. **Open the installed-apps page:** github.com/settings/installations, signed in. (The long way: profile picture, top right → **Settings** → **Applications** in the left sidebar, under "Integrations" → the **Installed GitHub Apps** tab.)
   2. **Find Pages CMS** and click **Configure** beside it.
   3. **Scroll down to "Repository access"**, set to **Only select repositories**.
   4. **Add the repository:** **Select repositories** → type its name → click it in the dropdown.
   5. **Click Save** (GitHub may ask for a password or security code). Then reload app.pagescms.org.
2. **Claude's access.** GitHub is connected to Claude, so Claude can attach a repository in a session and push to it. Claude cannot change repository Settings (e.g. turning on Pages) or delete repositories, and can't see GitHub's status page; with the Chrome extension connected it can read the Actions page and open and test the live site.

## B. Build and test the template (per template)

1. **Start from Alexander:** an own theme reading a department-defined content format (student content in Markdown/YAML files). Themes can later be swapped without touching student content or the Pages CMS forms. If a third-party theme is ever used instead: check its licence, copy it into `themes/`, write `.pages.yml` to match its content files, and override sections in the site's own `layouts/` rather than editing the theme.
2. **Create the repository** (empty, public) and get the files in: Claude pushes them, publish from GitHub Desktop, or upload via GitHub. If uploading by hand, hidden files (`.pages.yml`, `.github/workflows/hugo.yml`, `.gitignore`, `.gitkeep`) must be created with **Add file → Create new file**; the uploader skips them (see General note).
3. **Turn on Pages** in each copy that should publish: Settings → Pages → Source: **GitHub Actions**. Ignore the suggested starter workflows. (The Alexander template repository itself keeps Pages off; test template changes in a copy.)
4. **Add the repository to Pages CMS** (A1).
5. **Run the verification checklist** (section C).
6. **Remove test content** (the starter carries none), and remove unused uploads and placeholder files (e.g. the generated `static/files/resume.pdf`).
7. **Mark it as a template:** Settings → tick **Template repository**.
8. **Rehearse the student path** with "Use this template", following the student instructions exactly and timing each step. Fix the handout where you hesitate.

## D. Before handing it to students

- **Handout** (section H), with screenshots of the two steps that confuse people: granting Pages CMS access to the new repository, and re-running the first build (which always fails because Pages isn't on yet).
- **Image guideline:** see the best-practices page (section H). Project images 1800 × 1200 (3:2), under about 400 KB; Alexander makes smaller copies itself, so oversized uploads cost build time, not visitors' time. The wide card shows about the middle 60% of a 3:2 image's height; squarer images are shown whole there.
- **Username guidance:** the GitHub username appears in the address (`username.github.io/portfolio`), unless the student sets up their own domain (section H).
- **Deadline buffer:** set portfolio deadlines a day or more before reviews; GitHub build outages (like 11 Nov) block updates but usually not viewing.
- **Decide ownership:** students' own GitHub accounts (sites survive graduation; students need accounts) vs. department-owned repositories with email invites through Pages CMS (no student accounts; department decides what happens after graduation).
- **Decide visibility:** on GitHub's free plan Pages publishes only from public repositories, so students' Markdown and original uploads are readable on github.com (outside the site's AI opt-outs). GitHub Pro, free to verified students, allows private repositories; what happens to the site when Pro lapses after graduation is unconfirmed.
- **Decide distribution:** "Use this template" (students copy it themselves; includes hidden files) or GitHub Classroom (an assignment link makes each student's copy; instructor sees all copies). Avoid zip download and upload (the uploader drops hidden files; see General note). Forks work but arrive with automatic builds switched off.

## E. Changing the template after students have copied it

Copies made with "Use this template" are independent: later changes to the template **do not reach existing student copies**. So:
- Freeze and test the template before distributing.
- For a fix after distribution, either give students a one-file replacement to paste in, or accept that early copies differ. Each site's home page names the template version it runs (from 0.6.5), so faculty can see which copies are behind.
- **Updating a copy by hand** (done 22 Nov for Robert's and John's sites, 0.6.4 → 0.6.5, and 23 Nov for all three, 0.6.5 → 0.6.6): copy in every file the template changed since the copy was made (the theme folder, `.pages.yml`, README, docs), leaving `content/`, `data/` and `static/` alone; commit and push; the site rebuilds. Steps in CLAUDE-NOTES §5. It works cleanly only while the copy's own theme files are unedited.
- A structural alternative: load the theme as a Hugo Module at build time, so a theme update reaches every student on their next build. More setup; also means a theme change can break every site at once unless copies pin a version; `.pages.yml` would still live in each copy. Listed as a possible to-do (CLAUDE-NOTES §7).

## F. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Build red at "configure-pages" | Pages not turned on | Settings → Pages → Source: GitHub Actions; re-run. (Expected in the Alexander template repository, which keeps Pages off) |
| No "Publish site" run at all after an upload | `.github/workflows/hugo.yml` dropped by the web uploader | Create it with Add file → Create new file, or have Claude push it (see General note) |
| Run stuck in "Queued"; cancel fails | GitHub outage | Check githubstatus.com; wait |
| Several "cancelled" runs | Quick successive saves | Normal; only the latest run matters |
| Repository missing in Pages CMS | App not granted access | Add the repository to the Pages CMS app (A1, steps 1–5) |
| Form missing in Pages CMS | `.pages.yml` absent, misnamed, or not valid YAML | Create it with Add file → Create new file; for Alexander run `dev/check_content.py` |
| New or moved form fields don't show in Pages CMS | Pages CMS read the old `.pages.yml` when it loaded | Reload app.pagescms.org |
| An uploaded image doesn't replace the old one | Pages CMS saves a same-named upload as `<name>-1.jpg` | On the Images page: upload, delete the old file, rename the new one to the old name (runbook §2) |
| Seven suggested section headings reappear when editing a Brief (or any entry saved with no sections) | Pages CMS fills an empty Sections list with the suggested headings when the form opens | Delete them before saving; if saved, they are empty and don't show on the page (runbook pitfall 15) |
| Site has text but no styling or images | Path problem with the site living in a subfolder | Ask Claude; usually a template or path fix |
| Starter-workflow prompt (Jekyll, Static HTML) | GitHub's suggestions | Ignore; the repository has its own workflow |
| A link leads to a "404" page on the student's own site | Address typed without `https://`, so the browser treats it as a page inside the site | Type the full address. Repaired automatically in Alexander (every link) |
| Change saved, build green, but the page looks unchanged | Browser showing a saved copy (GitHub Pages files are cached for about 10 minutes) | Shift-reload, or wait 10 minutes. The Alexander README tells students so |
| Site address gives a 404, though the build is green | Wrong letter case in the repository part of the address (it is case-sensitive) | Copy the address from Settings → Pages |
| Alexander: yellow "Analytics:" warning in the Actions run | Analytics code not recognised | Student re-pastes the code in the Analytics form; the site publishes without analytics meanwhile |

## G. Lessons from building Alexander (19–23 November)

1. **Separating content from design is not enough; the shape of the content matters.** Every theme keeps content apart from templates, but each invents its own file layout and field names, so content written for one theme has to be moved for another. YAML lists in `data/` (one earlier theme's approach) also hold prose as strings that only make sense to the template reading them. Alexander's answer: a department-defined format, mostly one Markdown file per item, that any theme can be adapted to read.
2. **A template can only show what it knows to look for.** An earlier theme's Education entries had degree, school and year, and no field for prose; a description added by hand would never appear. The content format decides what kinds of statement a student can make.
3. **Decide which sections exist in one place.** In Alexander, one partial (`sections.html`) decides; the menu and the page both read it, so a menu button can never lead to an empty section.
4. **Let Hugo make the image sizes.** Students upload originals; the build makes WebP copies at several widths and the page lets each browser pick. This replaces the export-at-the-right-size advice as the main defence against heavy pages.
5. **Test in a narrow preview too.** The first layout switched columns on window width; inside a narrow preview panel it showed the phone layout. Container queries (layout by available space) fixed it.
6. **Self-hosted fonts are an alternative to both system fonts and Google Fonts.** Six open-licence variable fonts add about 1 MB to the repository but only the chosen ones (about 100–150 KB) reach a visitor, with no outside requests.
7. **Parse the configuration, don't just read it.** Alexander's `.pages.yml` carried a YAML error from 0.1.0 (an unquoted description containing a colon) that would have stopped Pages CMS loading the forms; found only when a script parsed the file. `dev/check_content.py` now parses it and every content file on each change.
8. **Accept what students will paste.** The Analytics field picks a code out of a whole address or snippet, and a bad code produces a build warning instead of a broken site. The same habit as the `https://` link repair: design the field for the mistake.
9. **Subfolder addresses limit more than looks.** `robots.txt` is read only at a host's root, and GitHub Pages sends no custom headers, so on `username.github.io/repo/` the AI opt-out rests on page tags alone. An own domain (student guide in H) moves the site to a root.
10. **Pages CMS rewrites the whole file on every save** (confirmed 21 Nov in its source and in the demo repository's commits). Fields are reordered to match the form, unneeded quotation marks dropped, comments deleted, empty fields removed, and keys with no form field discarded (unless `settings: content: merge: true` is set). Explanations therefore belong in field descriptions in `.pages.yml`, never as comments in content files. Its "block" field type, which switches between differently shaped sets of fields, would discard one set's text when a student switches; a plain select field over one form avoids that.
11. **Fix names where the site is built, not where files are uploaded.** Uploads keep their original names (spaces included); the theme gives the published copies clean names. This covers files already uploaded and asks nothing of students. Pages CMS's own upload renaming would have used hyphens and stripped underscores.
12. **What students see may be a cached page.** After a save the live site can show the previous version for up to ten minutes. Worth saying in the handout, and in the README (done).
13. **Moving a field between forms moves where its value is stored.** Analytics, the AI-training choice and the Search Console code left Profile (`content/_index.md`) for their own form (`data/analytics.yaml`), so the templates read the new file and the value had to be carried across by hand. In copies made before such a change, students must enter the setting again; defaults were chosen so that a missing value is the safe one (no analytics, AI training refused). Reordering fields inside one form, by contrast, changes nothing stored.
14. **A link's name should match what it opens** (22 Nov, from an outside review). Gallery thumbnails were named by their alt text, so a screen reader heard one name in the grid and another on the page it opened. Showing the title in the link fixed it without a new field. Check that grid, page heading and previous/next links share one name wherever an image is the link.
15. **A frame's shape changes with the screen, and a crop can remove the point of an image** (22 Nov, from an outside review). The wide card's frame runs from about 2:1 to 2.6:1, so a portrait kept about a third of its height. The template now reads each image's shape and shows squarer images whole, with no new field; a hint covers the rest. A separate cover image or crop anchor stays in reserve.
16. **Docs drift fastest in summaries** (22 Nov consistency pass). Status rows, the README's page descriptions and the standards list kept statements a later version had changed (Kind field "untested", "seven forms", a contrast figure, "no analytics"). Reread the summaries, not only the history, after each version. Refactors that should change nothing are checked with before-and-after screenshots compared pixel by pixel.
17. **An empty starter needs placeholders to keep its folders** (22 Nov). Git drops empty folders, and Pages CMS saves collections into folders that must exist, so the bare starter keeps a `.gitkeep` in each content and image folder. Hugo ignores them. Built empty, the site shows only the name and the closing block; nothing breaks.
18. **Keep one authoritative copy** (22 Nov). A demo repository, a zip and a text copy in the Project drifted apart within a day (two READMEs, two versions of DESIGN.md). The template repository is now the only copy of the theme; the Project holds docs about it.
19. **A copy should say what it was made from** (22 Nov). Once the template changed under its copies (the Tools hint), nobody could tell which version a site ran. From 0.6.5 every home page names its template version, the worksheet carries a version line and change log, and worksheet copies a provenance line.
20. **Help text is part of the template** (22 Nov). A Tools note copied from one project read on the home page as a general claim about the tool. The fix went into the form's hint, the worksheet and both student guides, so the guidance meets students where they type.
21. **Revising is a different task from filling** (23 Nov, all three persona sites revised). Most of the work was diffing a new worksheet against the last record and touching only what changed: appending a sentence, adding a section to a finished project, moving one job's Order. Students will spend more time revising than filling, so the record of what the site currently says (a worksheet kept up to date) matters as much as the first draft.

22. **Rename labels, not internals** (23 Nov, 0.6.6). Renaming Projects to Selected Work changed only what people read (headings, menu, form labels, hints); the folder `content/projects`, the stored kind values and the addresses stayed, so existing copies took the change by a file swap with no content moved. A longer label still has a layout cost: the menu wrapped.

23. **A session may not be able to build** (24 Nov, 0.6.7). The shell on Garrison's Mac is a separate Linux machine: it can't run programs installed on the Mac, and its allowlist blocked the Hugo download, so 0.6.7 was written and checked by reading only. Ways round it: Garrison runs `hugo server` and Claude looks at the local address in his Chrome; or the change goes to one persona copy first and is checked there.
