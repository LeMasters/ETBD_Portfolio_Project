# ETBD Portfolio Project

> **Caveat lector:** This document was mostly generated by Claude AI. Questions and corrections to Garrison LeMasters (ETBD).

How undergraduates in Miami University's Department of Emerging Technology in Business and Design, ETBD and Games + Simulation majors alike, build and publish professional portfolios. This page is the quick overview for faculty reviewers and is kept up to date; the files listed at the end go deeper.

## What this is

Students in both majors publish their portfolios with **Alexander**, a free template at prototype version 0.6.7 (November 2026). A student fills in web forms; the site builds and publishes itself. No coding, no hosting fees.

Alexander is a custom theme Garrison LeMasters designed as a flexible starting point for this project. It is one-size-fits-all, and therefore imperfect. Over time we can introduce other themes, also custom-built by us, and/or give students the documentation to build their own theme (not a beginner-friendly project at all).

Three sample portfolios show what it produces. They belong to composite student personas, not real students.

## How it works

Three free services do the work. Students use only the second.

| Service | What it does | Link |
| --- | --- | --- |
| GitHub | Holds each student's copy of the template and publishes the site at `username.github.io/repository` | [Alexander template repository](https://github.com/LeMasters/portfolio_template_Alexander) |
| Pages CMS | The web forms students fill in: profile, selected work, gallery, experience, education, tools, appearance, analytics | [pagescms.org](https://pagescms.org) |
| Hugo | Turns what students typed into the web site, on every save | [gohugo.io](https://gohugo.io) |

1. A student copies the template on GitHub (**Use this template**) and turns on publishing. This is done once.
2. The student fills in the forms in Pages CMS and uploads images.
3. Each save rebuilds the site; changes appear within a minute or two.

Student content is stored as plain text files, separate from the design, so it can move to another theme later.

## What the stored files look like

Each piece of work is one Markdown file: labelled fields at the top (title, kind, caption, image, sections), then the description as ordinary text. Pages CMS writes these files; Hugo turns them into pages. Two examples, as stored and as published:
